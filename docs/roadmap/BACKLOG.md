## Hoja de ruta de experiencias UX (orden acordado con el CPSAO, 2026-07-11)

Cada "experiencia" se ejecuta como una `FIN` propia, bajo la regla ya vigente "un FIN
a la vez" — no se abre la siguiente experiencia hasta cerrar la anterior. Ciclo por
experiencia: Propuesta → Implementación → Capturas reales → Revisión CPSAO → Ajustes
→ Aprobación.

1. **Experiencia de Inicio** — `FIN-017` (Login + Dashboard), verificada por el CTO,
   pendiente de `IMP-0017` y cierre formal. **Estándar de captura ampliado (CPSAO,
   2026-07-11):** la revisión completa de cierre ya no se limita al primer pantallazo
   (above-the-fold) — el Arquitecto debe entregar capturas consecutivas de todo el
   recorrido vertical de cada pantalla (Login + Dashboard completo con scroll), para
   evaluar jerarquía, ritmo de lectura, continuidad visual y utilidad de cada sección
   de principio a fin, no solo el encabezado. Con esa evidencia completa se decide si
   Inicio necesita una nueva iteración (`FIN-018` sobre la misma experiencia, sin
   romper "un FIN a la vez") o si avanza a la Experiencia de Salud — la decisión se
   toma después de ver la experiencia completa, no antes. Principio reafirmado por el
   CPSAO: "no avanzamos porque una pantalla funcione, avanzamos cuando representa el
   nivel de calidad que queremos para Milla."
2. Experiencia de Salud.
3. Experiencia de Presupuesto.
4. Experiencia de Deudas.
5. Experiencia del Simulador.
6. Experiencia del Copiloto.

**Aclaración del CTO sobre la excepción técnica que el CPSAO permite:** "el resto del
producto puede avanzar técnicamente cuando no exista dependencia" se interpreta como
correcciones puntuales bajo la Regla de Acciones Correctivas o defectos triviales (p.
ej. el bug ya identificado de la ruta `MilloPlus` no registrada) — **no** como
autorización para abrir una segunda `FIN` de experiencia en paralelo. La disciplina
"un FIN a la vez" no se relaja para el trabajo de UX.
